# Уборка в проекте

Цель: следующая сессия агента открывает проект и сразу понимает, что это, где мы и что дальше. Ничего не удаляй: временное и устаревшее переноси в `_temp/` внутри проекта.

## Память проекта: один факт - один файл

| Файл | Что в нем | Чего в нем нет |
|---|---|---|
| `CLAUDE.md` (для Codex - `AGENTS.md`) | брифинг агенту: что за проект в 2-3 предложениях, неочевидные правила и грабли, команды, ссылки на README и progress. До 50 строк, потолок 100 | описаний файлов |
| `README.md` | навигация: таблица «файл - что это», методология, как воспроизвести | задач и хронологии |
| `progress.md` | вехи: этап, решение с «почему», итоговый артефакт, урок. Блок «Текущий этап» - точка входа для новой сессии | списка задач |
| `PRD.md` | требования: зачем, для кого, что входит и не входит, критерии готовности | хода работы |
| `KANBAN.md` | все задачи: «Бэклог», «В работе», «Готово», одна строка на задачу с датой | всего остального |

Нашел один и тот же список или команду в двух файлах - оставь в файле-владельце, из второго убери и поставь ссылку.

Если просят «разверни окружение» в новом проекте: папка, `git init`, для Python - `venv`, и сразу пять файлов из таблицы.

Для Codex и Claude Code одновременно: правила в `AGENTS.md`, а в `CLAUDE.md` одна строка `@AGENTS.md`.

## Уборка

- Временные файлы, черновики и файлы завершенных этапов - в `_temp/`.
- Если в корне накопились файлы, которые логичнее разнести по подпапкам, - разнеси.
- Отладочный мусор в коде (`print` для отладки, `console.log`, закомментированные эксперименты) - убери.
- В подпапках со своими `CLAUDE.md` и `README.md` - синхронизируй и их.

## Сверка с реальностью (обязательно)

1. Список файлов в корне против таблицы в README: новое опиши, исчезнувшее убери из таблицы.
2. Если `CLAUDE.md` и README заметно старше свежих артефактов - прошел этап, которого память не видела. Прочитай progress и свежие файлы, догони.
3. Проверь 2-3 пути из памяти на существование.
4. «Текущий этап» в progress отражает реальность? Была значимая работа без вехи - допиши веху.
5. В KANBAN сделанное перенеси в «Готово», давно закрытое - в `_temp/kanban-archive.md`. Задачи, лежащие в progress, перенеси в KANBAN.
6. PRD сверь с тем, что сделано. Расхождение - вопрос пользователю, а не молчаливая правка требований.

## Повторяемое - в скилл

Если в работе появились правила, которые понадобятся снова (как писать раздел ТЗ, как искать данные), предложи вынести их в отдельный файл или скилл проекта и сослаться из `CLAUDE.md`.

## Автопамять агента

Если у агента есть своя память о проекте: то, что уже есть в файлах проекта, из памяти убери (с согласия пользователя). Правила, нужные коллегам, переноси в проект: память агента видит только он.

## Завершение

1. Если проект под git и есть изменения - покажи `git status` коротко и предложи коммит. Без согласия не коммить.
2. Сводка: что перенесено, что синхронизировано, какие расхождения нашел и как починил.
