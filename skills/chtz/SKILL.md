# ЧТЗ на доработку 1С

Три шаблона рядом с этим файлом:

| Файл | Когда |
|---|---|
| `templates/kartochka.md` | хотелка заказчика еще сырая: сначала карточка задачи и вопросы |
| `templates/chtz.md` | карточка согласована: пишем ЧТЗ |
| `templates/chek-list.md` | ЧТЗ написано: проверяем перед отправкой |

## Порядок

1. Спроси, что есть: хотелка, карточка, ответы заказчика, база с MCP. Если хотелка без карточки - начни с карточки.
2. Материалы заказчика бери только обезличенные (`*.anon.*`). Видишь пароль, ФИО, телефон - остановись и скажи об этом.
3. Перед тем как писать раздел, найди в базе объекты, которые он затрагивает: через MCP (`list_metadata_objects`, `get_metadata_structure`) или в выгрузке исходников. Покажи пользователю список найденного.
4. Пиши ЧТЗ по шаблону по одному разделу. После каждого раздела остановись и дай пользователю проверить.
5. В конце пройди `templates/chek-list.md` и отчитайся по каждому пункту: выполнен / нет / что поправить.

## Правила

- Имена объектов метаданных пиши только те, что нашел в базе. Новый объект помечай «(новый)». Не уверен - пиши «уточнить», не выдумывай.
- Имена объектов в виде **Тип.Имя** жирным: **Справочник.Номенклатура**, **Документ.ЗаказПокупателя**. Моноширинным только пути, адреса и примеры значений.
- ЧТЗ описывает что и как должно работать: объекты, реквизиты с типами, формы, поведение, права. Как это написать в коде, решает разработчик.
- Типовую конфигурацию не меняем, доработки в расширении с префиксом.
- У каждого пункта технической реализации три части: «Как сейчас», «Требование», «Реализация», и в конце «Как проверить» с ожидаемым результатом.
- Решения, которых не принимал заказчик, не записывай как решенные: выноси в «Открытые вопросы».
- Пиши просто: короткие фразы, без канцелярита. Пример значения у каждого нового реквизита.
