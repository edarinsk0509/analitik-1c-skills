# Чек-лист проверки ЧТЗ

| № | Проверка | Как проверить |
|---|---|---|
| 1 | Указаны конфигурация, версия, платформа и расширение | паспорт и п. 6.1 |
| 2 | Все имена объектов есть в базе, новые помечены (новый), сомнительные - «уточнить» | каждое имя найти через MCP или в исходниках |
| 3 | У каждого нового реквизита есть тип, обязательность и пример | таблицы реквизитов |
| 4 | У каждой цели есть проверяемый критерий | раздел 3 |
| 5 | Каждое функциональное требование раскрыто в технической реализации | раздел 5 против раздела 6 |
| 6 | У каждого пункта реализации есть «Как сейчас», «Требование», «Реализация», «Как проверить» | раздел 6 |
| 7 | В «Как проверить» есть ожидаемый результат, а не только действие | раздел 6 |
| 8 | Описано, что происходит при ошибке: не заполнено, дубль, нет прав | проверки при записи |
| 9 | Типовая конфигурация не меняется | п. 6.1 |
| 10 | Права расписаны по ролям | раздел «Роли» |
| 11 | Нет решений, которых не принимал заказчик: они в открытых вопросах | раздел 7 |
| 12 | Нет кода и названий процедур, кроме случаев, когда без них нельзя | весь текст |
| 13 | Нет данных заказчика, которые не должны попасть в документ: пароли, личные данные | весь текст |
| 14 | Текст читается без знания 1С в разделах 3-5 | прочитать как заказчик |
